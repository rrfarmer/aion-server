# Phase 6 Bind-Point Teleport Known-List Population Packet Fact Sources

Date: May 26, 2026
Unit of Work: UOW-1276
Scope: Add source-origin metadata for population packet construction facts.
Source of truth: Java project.

## Summary

UOW-1276 extends population packet-construction metadata so diagnostics can distinguish request-level packet construction facts from facts generated by per-direction fact plans.

This remains a C# staging diagnostic. Java reads live runtime player/controller/effect/stat state rather than merging request and generated fact dictionaries. The existing C# rule remains unchanged: request-level packet facts are authoritative, and generated fact-plan facts only fill missing subject player object ids.

No live packets are sent, no Java `KnownList` callbacks are executed, and no world or socket state is mutated.

## C# Implementation

Updated `dotnetConversion/src/Aion.GameServer/Services/PlayerKnownListPopulationPlanService.cs`:

- added `PlayerKnownListPopulationPacketConstructionFactSourceKind`;
- added `PlayerKnownListPopulationPacketConstructionFactSource`;
- candidate plans now expose `PacketConstructionFactSources`;
- source metadata records:
  - request-level packet facts;
  - generated fact-plan facts that were accepted;
  - generated fact-plan facts ignored because request-level facts for the same subject already existed.
- request-level source rows are filtered to subject ids consumed by the candidate's attached side effects, so unrelated request-wide facts do not inflate candidate diagnostics.

Updated `PlayerKnownListPopulationPacketConstructionDiagnosticService`:

- candidate diagnostics expose packet fact source metadata;
- root diagnostics aggregate packet fact source totals;
- root diagnostics aggregate source counts by source kind.

## Remaining Risks

- Source-origin metadata is a C# staging diagnostic, not Java behavior.
- Live Java reads runtime state; C# still relies on supplied facts or generated supplied-snapshot facts.
- Request-level facts remain authoritative by C# design; future live adapters must not treat this as Java ordering.
- Pet visibility remains unmodeled.
- Threading and locking remain metadata-only.
- Serialization evidence is indirect except for the existing ride packet payload assertion.
- Date/time behavior for effects and motions remains unverified.
- Reflection behavior did not change.
