# Trade List Java Vector Generator Skeleton Feasibility

Date: May 26, 2026
Unit of Work: UOW-1172

## Purpose

This document records whether a Java-side trade-list vector generator skeleton can be safely added and compiled in the current repository state.

Java remains the source of truth. This unit does not add generator code, does not generate artifacts, and does not claim runtime parity.

## Maven/Test Layout Findings

The repository uses a non-standard but explicit Maven layout:

- root `pom.xml` declares modules for `chat-server`, `commons`, `game-server`, and `login-server`;
- root `pom.xml` sets `maven.compiler.release` to `25`;
- root `pom.xml` sets `maven.test.skip` to `true` by default;
- `game-server/pom.xml` sets `<sourceDirectory>src</sourceDirectory>`;
- `game-server/pom.xml` sets `<testSourceDirectory>test</testSourceDirectory>`;
- `game-server/pom.xml` already has a JUnit Jupiter API test dependency;
- `game-server/test` already contains Java test/proof classes.

Existing game-server test/proof files:

- `game-server/test/com/aionemu/gameserver/services/cron/CronServiceTest.java`
- `game-server/test/com/aionemu/gameserver/model/stats/container/CreatureLifeStatsTest.java`
- `game-server/test/com/aionemu/gameserver/network/aion/LoopbackCaptureProof.java`

`LoopbackCaptureProof` is the closest precedent for a standalone opt-in runtime capture utility. It has a `main` method, is intentionally not a default JUnit test, and documents that process shutdown is needed after its proof run.

## Feasibility Assessment

Adding a trade-list generator skeleton is feasible in the repository layout, but not safe to implement locally until Java 25 JDK and Maven are available.

Recommended future package:

```text
game-server/test/com/aionemu/gameserver/parity/trade/
  TradeListVectorGenerator.java
  TradeListVectorScenario.java
  TradeListPacketCapture.java
  CanonicalPacketWriter.java
```

Recommended compile command once tooling exists:

```text
mvn -pl game-server -am -Dmaven.test.skip=false -DskipTests test-compile
```

Recommended opt-in run command shape after compile succeeds:

```text
java -cp "<resolved game-server test/runtime classpath>" \
  com.aionemu.gameserver.parity.trade.TradeListVectorGenerator \
  --scenario buy-sellable-normal \
  --output parity-artifacts/trade-list/java \
  --player-object-id 1001 \
  --npc-object-id 9001 \
  --npc-id 203060 \
  --player-legion-level 0 \
  --vendor-buy-modifier 100
```

The exact runtime classpath should be generated by Maven when tooling is available. Do not hand-maintain a large classpath in the repository.

## Safe Skeleton Rules

When tooling exists, a first skeleton should:

1. Live under `game-server/test`, not `game-server/src`.
2. Avoid production startup changes.
3. Avoid modifying production packet classes.
4. Emit a schema-only JSON file or a dry-run scenario manifest before attempting packet bytes.
5. Compile with `test-compile` before any artifact is checked in.
6. Mark output `captureLevel = "skeleton"` until it executes Java `DialogService` or packet constructors.
7. Keep generated artifacts out of source control until reproducibility is proven.

## Known Blockers

- Maven is not available locally.
- `javac` is not available locally.
- Installed Java runtime is `1.8.0_491`, but the repository requires Java 25.
- Existing `LoopbackCaptureProof` remains uncompiled/unrun in this environment.
- The generator will likely need either reflection over packet internals or test-only accessors; that choice should be made with compile feedback.
